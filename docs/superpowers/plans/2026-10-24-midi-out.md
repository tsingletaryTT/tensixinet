# MIDI and CV out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hand the devices' own events (notes, triggers, controls) out as data, and turn them into a MIDI file and a live MIDI port, with a seam a CV sink can use later.

**Architecture:** A new `tensixinet/score/` package. `collect.py` builds a `Score` from the same code paths that make the audio (the lead and `ttrollz` are split so the audio reads the event list). `routing.py` and `midi.py` turn a Score into timed MIDI bytes. `smf.py` writes a file. `sinks.py` has a file sink and a live-port sink. `cli.py`, `run.py` and `live.py` hand each render's Score to the sinks.

**Tech Stack:** Python 3.10+, numpy. `mido` and `python-rtmidi` as an optional extra, imported only for `--midi-port`.

**Spec:** `docs/superpowers/specs/2026-10-24-midi-out-design.md`

## Review Focus

- A chip with no events in a segment (all rests, idle under eviction) gives an empty list and writes a valid file with no notes.
- A note that is still sounding when the segment ends gets its off at the segment's end, so no note hangs on a port or in a file.
- A pitch above or below the MIDI range, and a bend curve that moves more than the route's bend range, are clamped, not wrapped.
- Two events at the same time on the same channel keep a stable order (offs before ons).
- `--midi-port` with the library missing, or a port name that does not exist, ends with one plain message and exit code 2, before any chip is read.
- A port that errors mid-run does not stop the audio.

### Task 3: Device extractors

**Files:**
- Create: `tensixinet/score/collect.py`
- Test: `tests/score/test_collect.py`

**Interfaces:**
- Consumes: Task 1 types; `lead_notes`, `ttrollz_pulse_sets`, `strike_times`, `step_times`, `step_pattern`, `ttquantus_steps`, `ttquantus_gate`, `temp_to_pitch_hz`, `chip_pressure`, `chip_chaos`, `personality` from the existing modules.
- Produces, in `collect.py`, each taking one chip's `Telemetry` plus `chip: int`, `duration`, `sample_rate`, `seed`, `patch`, and `segment` where the device has one, and returning a list of events with velocity or strength 1.0 (the caller scales them):
  - `lead_events(...) -> List[Note]` (source `"lead"`).
  - `quantus_events(...) -> List[Note]` (source `"ttquantus"`): one note per eighth whose gate (sampled at the middle of the note) is above 0.5; `pitch_hz` is `temp_to_pitch_hz(t.asic_temperature) * 2 ** (semis_at_note_start / 12)` with the semitone value read at the note's first sample; `bend` holds `(seconds into the note, semitones minus the starting semitones)` sampled every 20 ms from the same per-sample array, so glide and vibrato appear; consecutive notes with the same pitch are separate notes.
  - `gong_events(...) -> List[Trigger]` (source `"gong"`, `strike_times`).
  - `roll_events(...) -> List[Trigger]` (source `"ttrollz"`, `lane` = lane index, `strength` 1.0 for a cycle start and 0.6 for an ordinary pulse; the clock is lane `-1`).
  - `steam_events(...) -> List[Trigger]` (source `"ttsteam"`: the register's step times where the column mask has a hit, thinned by the patch's `snare` share with the same rule `ttsteam` uses; read `ttsteam` and reuse its selection, moving it into a shared function if it is inline).
  - `control_events(t, chip, segment_seconds) -> List[Control]`: at `t = 0`, names `"temperature"`, `"power"`, `"pressure"`, `"chaos"`, each 0 to 1 (`pressure` and `chaos` from `chip_pressure`, `chip_chaos`; temperature and power scaled over the ranges `mapping.py` already uses, clamped).

**Interfaces:**
- Consumes: Task 1 types.
- Produces:
  - `@dataclass(frozen=True) class Routes: note_channels: Mapping[str, int]; trigger_notes: Mapping[str, int]; roll_lane_notes: Tuple[int, ...]; control_ccs: Mapping[str, int]; control_channel: int; pulse_s: float; bend_range: float` with channels 0 to 15 (stored zero-based; docs say 1-based).

  - `load_routes(path) -> Routes`: JSON file with any subset of those keys, merged over `DEFAULT_ROUTES`; unknown keys, a channel outside 0-15, a note or CC outside 0-127 raise `ValueError` naming the key.
  - `to_messages(score: Score, routes: Routes = DEFAULT_ROUTES) -> List[Tuple[float, bytes, int]]`, sorted by time, as `(seconds, raw bytes, chip)`: a note is a pitch-bend message (set to the note's starting remainder, scaled by `bend_range`) before its note-on, bend messages for each `bend` point (clamped to the range), then note-off at `t + dur`; a trigger is a note-on at `round(127 * strength)` velocity (minimum 1) and an off `pulse_s` later; a control is one CC (`round(127 * value)`) per `(chip, name)` whenever the integer changes; a note velocity is `round(127 * velocity)`, minimum 1. Notes outside 0-127 are clamped by octaves toward the range. At equal times offs come before ons, bends before ons, then input order. A note still sounding at `score.duration` gets its off at `score.duration`.

### Task 7: Live wiring and the live MIDI port

**Files:**
- Modify: `tensixinet/score/sinks.py`, `tensixinet/live.py`, `tensixinet/cli.py`, `pyproject.toml`
- Test: `tests/score/test_sinks.py`, `tests/test_live.py`, `tests/test_cli.py`

**Interfaces:**
- Produces:
  - `MidiPortSink(port_name: str, routes: Routes = DEFAULT_ROUTES, offset_ms: float = 0.0, open_output=None, clock=time.monotonic, sleep=time.sleep)`. `open_output(name) -> port` where a port has `send(raw: bytes)` and `close()`; the default opener imports `mido` and `rtmidi` lazily and opens the named output, or a virtual output called `tensixinet` when `port_name == "virtual"`, and raises `MidiPortError` (a `RuntimeError`) with a one-line message when the library is missing or the port is not found. `add(score, start_s)` pushes messages onto a time-ordered heap with `time_base + start_s + seconds + offset_ms / 1000`, where `time_base` is the clock when the first `add` happens; a scheduler thread sends what is due, sleeping until the next. `close()` sends note-off for every note still on and CC/bend reset on each channel used (all-notes-off, `0xB0 | ch, 123, 0`), stops the thread. A send that raises logs once (`on_error` callable argument, default no-op) and the sink drops everything after that. `add` never blocks and never raises.
  - `run_live` takes `score_sink=None`. After each segment's `render_chorus`, it builds `chorus_score(chips, seconds + XFADE_S, patch, segment, [soloist], only=only, defrag=..., sample_rate=sample_rate)` with the same arguments the render got, drops events whose `t >= seconds`, cuts notes at `seconds`, and calls `add(score, segment_start_s)` where `segment_start_s` is the sum of the earlier segments' `seconds`. It never changes the audio path.
  - CLI: `--midi-port NAME` (`virtual` allowed; needs `--live`), `--midi-offset-ms MS` (float, default 0, only with `--midi-port`). The port is opened before any chip is read, so a missing library or port ends with one message and exit code 2. `--midi-file` and `--midi-port` together use a `TeeScoreSink`. `pyproject.toml` gains `midi = ["mido", "python-rtmidi"]` under optional dependencies.
