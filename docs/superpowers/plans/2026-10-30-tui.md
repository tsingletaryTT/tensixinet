# `--tui` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `tensixinet --live --tui` draws a full-screen terminal view of what is being heard: the chips, the devices dealt to them, who has the floor, the strongest cables, the stereo field and a colour-coded run log. `--with-tt-toplike --tui` puts that view in the synth pane beside tt-toplike.

**Architecture:** A new package `tensixinet/tui/`. A pure renderer turns a `FlowState` (`ui/flow.py`, the same data the Gradio chart draws) and a list of run-log records into a `Frame`: rows of styled text spans. A `Playhead` holds what the loop has handed to the sink, keyed by its offset in the audio, and gives back the state and log lines the listener has reached. The listener's time starts at the first write to the sink, as `ui/session.py`'s `Session._pending` does. `run_live` and `run_fast` each get an `on_segment` hook at the point where they queue audio for the sink. `RunLog` gets an `on_event` hook. A driver (`TuiApp`) owns the terminal on its own thread: alternate screen, cbreak keys, redraw of changed cells only, SIGWINCH, `q`. The CLI adds `--tui`. In TUI mode the run log goes to the `.txt` file and the JSONL only.

**Tech Stack:** Python 3.10+ standard library (`termios`, `tty`, `signal`, `select`, `threading`, `_thread`), numpy (already used), pytest. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-30-tui-design.md`. Its "Decisions from the builder check" section is binding.

## Global Constraints

- **Size.** 80 columns by 24 rows is the target. Below 60 columns or below 16 rows the screen shows one line saying the terminal is too small, and the run carries on. Pin `MIN_COLS = 60`, `MIN_ROWS = 16`, `TARGET = (80, 24)`.
- **Chips.** One box per chip, at most `CHIPS_PER_ROW = 4` boxes in a row. More than four chips wrap into further rows of boxes, and the log gets fewer rows. Devices are one-line rows inside their chip's box. They are not boxes.
- **Cables.** Only the five most strongly pushing cables are listed: `CABLE_ROWS = 5`, sorted by `push`, strongest first.
- **Dim levels.** Three stepped dim levels below full brightness, from the mix's own `PRESENCE` table (`music/evict.py`: running 1.0, filling 0.6, evicting 0.25, idle 0.05): `dim_level(presence)` gives 0 at 0.9 or more, 1 at 0.5 or more, 2 at 0.2 or more, and 3 below that. So running is 0, filling 1, evicting 2 and idle 3. In colour a level scales the jack's RGB by `DIM_SCALE = (1.0, 0.7, 0.45, 0.25)`.
- **Focus.** The soloist's device row and the box of the chip that plays it are bold at dim level 0 and use heavy edge glyphs (`┃`, `┗━`). Every other device row is not bold and is at least dim level 1. Other chip boxes are not bold and use light glyphs (`│`, `└─`). The soloist is found by `DeviceView.soloist` (its slot), never by name: with 12 or more chips a device name is dealt to more than one chip.
- **No colour** (`NO_COLOR`, `--color never`, or not a terminal): no SGR colour codes in the frame. Focus still shows: the soloist's row starts with `▶` and its name is in brackets, and the focused box keeps its heavy glyphs. A chip that is not running shows its phase label and a marker character: `PHASE_MARK = {"running": " ", "filling": "+", "evicting": "-", "idle": "."}`.
- **Borders.** Left edges and bottom bars only. No right-hand border character anywhere (the global rule).
- **Keys.** `q` (or `Q`) and Ctrl-C both end the run the way Ctrl-C does now: the WAV and the logs are written out. `q` calls `_thread.interrupt_main()`. The terminal is put in cbreak mode, which keeps `ISIG`, so Ctrl-C still sends SIGINT. A resize (SIGWINCH) redraws the whole screen. No mouse, no scrolling keys.
- **Flags.** `--tui` needs `--live`. Without it the parser error is: `--tui needs --live: it draws what is playing as it plays, and an offline run plays nothing`. It works with `--mock-chips`, `--interval`, `--kernels` and `--with-tt-toplike`. The MIDI flags follow the loop in use: they stay refused with `--interval`, as now.
- **What is shown follows what is heard.** A segment's state, and every log record logged while that segment was being made, are shown when the listener reaches that segment's offset in the audio. The listener's time is `clock() - t0 - buffer_s`, where `t0` is the clock at the first write to the sink. In fast mode `buffer_s` is the player buffer the delay report already uses (`fast.player_buffer_s`); the lead is already inside the offsets. In plain live mode `buffer_s = 0`: the player was started without a latency request, and its buffer is not known.
- **Off the audio path.** The loops only call `Playhead.hand_over` and `Playhead.note`, which take a lock, append and return. Rendering and terminal writes happen on the TUI's thread. A terminal that blocks makes that thread drop frames; it never holds up the loop. `FRAME_S = 0.1` (10 frames a second at most).
- **Exit.** On every exit (normal end, `q`, Ctrl-C, an error code, an exception) the TUI leaves the alternate screen, shows the cursor and restores the terminal mode first. Then it prints the last record's `what` and the log directory. On an exit code other than 0 and 130, it prints the last `ERROR_RECORDS = 5` records (what and why) and `its log is in <dir>`, so the "Press Enter" message from `media/toplike.py` shows under them.
- **Log.** `KEEP_RECORDS = 400` records are kept. Each record is one `[mm:ss.s] what` line, wrapped, followed by its `why` in dim grey. A `why` already shown is left out, as the terminal log's `dedupe_why` does. The log scrolls to the newest line by itself.
- The rules in `CLAUDE.md`: test first, then a mutation check (and check that the test was green before the mutant; a mutation script that matches nothing proves nothing, so the script must print what it replaced). SPDX header on every new `.py`. A test file in the matching `tests/` folder for every new module, and an `__init__.py` in `tensixinet/tui/` and `tests/tui/`. No `ttnn`, `ttl`, `ttml`, `torch` or `sounddevice` imports. Docs that name flags or numbers change in the same task as the code.
- Run tests with `.venv-app/bin/python -m pytest`. Record the full-suite count before Task 1 (the last log entry says 3051 passed, 82 skipped, before the uncommitted tmux-config and styles work in the tree).
- The working tree already has uncommitted changes by the owner (`cli.py`, `media/toplike.py`, `tests/test_cli.py`, `tests/media/test_toplike.py`, `music/styles.py` and docs). Build on them and do not revert any of them.
- **Nothing is committed.** The owner's rule: no task commits. Every task ends with the changes left uncommitted.
- Never `pkill -f` or `pgrep -f`; use PID files. No gozer lease is needed: `--mock-chips` and `tt-smi -s` open no device.

### Task 1: The renderer: a `FlowState` and the log rows become a `Frame`

**Files:**
- Create: `tensixinet/tui/__init__.py` (SPDX header and a one-line docstring only)
- Create: `tensixinet/tui/frame.py`
- Create: `tensixinet/tui/layout.py`
- Create: `tests/tui/__init__.py`, `tests/tui/test_frame.py`, `tests/tui/test_layout.py`

**Interfaces:**
- Consumes: `FlowState`, `ChipView`, `DeviceView`, `CableView` (`ui/flow.py`); `PRESENCE` (`music/evict.py`); `CHIP_JACKS`, `DEVICE_JACKS`, `JACK_HEX`, `_rgb`, `_cube`, `bar` (`narrate/color.py`); `CABLE_COLOURS` (`ui/chart.py`).
- Produces, in `frame.py`:
  - `@dataclass(frozen=True) class Style: jack: Optional[str] = None; bold: bool = False; dim: int = 0`
  - `@dataclass(frozen=True) class Span: text: str; style: Style = Style()`
  - `Row = Tuple[Span, ...]`
  - `@dataclass(frozen=True) class Frame: rows: Tuple[Row, ...]; width: int; height: int` with `text() -> List[str]` (plain text of each row), `cells() -> List[List[Tuple[str, Style]]]` (each row padded with blanks to `width`, exactly `height` rows), and `find(text) -> List[Tuple[int, int, Style]]` (row, column and style of each span whose text contains `text`).
  - `dim_level(presence: float) -> int` with the thresholds in Global Constraints; `DIM_SCALE`.
  - `sgr(style: Style, colour: bool, truecolor: bool) -> str`: the escape that sets `style` (`ESC[0m` first, then `1;` for bold, then the jack's RGB scaled by `DIM_SCALE[style.dim]` as `38;2;r;g;b`, or `38;5;n` from `_cube`). `""` when `colour` is false. A `Style()` with no jack is the reset alone.
  - `fit(text: str, width: int) -> str`: `text` cut to `width`, the last kept character replaced by `…` when cut.
- Produces, in `layout.py`:
  - `LABELS = {"ultrasonic_shimmer": "shimmer"}`; `label(name) -> str` (any other name is itself).
  - `STEREO_CODES = {"ttrollz": "R", "ttrax": "X", "ttquantus": "Q", "ttdrone": "D", "lead": "L", "gong": "G", "ultrasonic_shimmer": "S", "ttsteam": "M", "ttavdog": "A", "ttchoir": "C", "ttcoco": "K"}`
  - Constants: `MIN_COLS = 60`, `MIN_ROWS = 16`, `CHIPS_PER_ROW = 4`, `CABLE_ROWS = 5`, `DEV_COL_W = 20`, `BAR_W = 4`, `LOG_MIN_ROWS = 3`, `PHASE_MARK`, `CABLE_STEPS = ((0.5, 0), (0.25, 1), (0.1, 2))` (push at or above the bound gets that dim level, below the last gets 3; bold at level 0).
  - `heading(state: Optional[FlowState], unit: str) -> str`: `"segment 3 · 4.0 s · gong on chip 1 has the floor"` for `unit="segment"`, `"phrase 3 · gong on chip 1 has the floor"` for `unit="phrase"`, `"... · nobody has the floor"` when `soloist_device == ""`, and `"waiting for the first segment to play"` (or `phrase`) when `state` is None. Then ` · <style or plain patch> · scale <scale> · gong <tuning>` when it fits.
  - `render(state: Optional[FlowState], log: Sequence[Row], width: int, height: int, colour: bool, unit: str = "segment") -> Frame`. `log` is the log pane's rows, oldest first (Task 2 makes them); `render` shows the newest that fit.

**Layout (pinned so the tests can say it):** top to bottom: the heading (1 row); the chip boxes; the stereo line (1 row, `L ` + field + ` R`); `cables (k of n, strongest first)` and up to `CABLE_ROWS` rows; then the log in every row left. Each box is `width // min(n, CHIPS_PER_ROW)` wide. A box is three header rows (`chip N` and its stereo home as `L.62`, `R.30` or `C`; the phase label with its mark; `52C 34W p31%`), then the chip's device rows (in columns of `DEV_COL_W` when the box is at least twice that wide), then the bottom bar. A device row is `▶ ` or two spaces, the label, then a `BAR_W` share bar (`bar(min(1, share * 4), BAR_W)`, the scale the chart uses) when it fits. A cable row is `kind source → target` plus a 6-wide push bar, in `CABLE_COLOURS[kind]`. When rows run short: the log keeps `LOG_MIN_ROWS`, cables are cut from the bottom, then whole rows of boxes are dropped and one row says `+N more chips`. Below `MIN_COLS` x `MIN_ROWS` the frame is one row: `terminal too small for --tui ({w}x{h}, needs 60x16); the run goes on`.

When `start` was never called it only writes the exit lines.
